# 审核元数据质量

你的任务是对当前库的全部项目进行元数据质量审核，生成结构化报告。**只审阅，不修改数据**。

---

## 全局约束

- **只读操作**。不要调用任何写操作（create/update/add_tag/remove_tag/add_file/remove_file）。
- **以项目为单位组织**。每个项目列出其全部问题。
- **数字要准确**。不要估算，所有计数必须来自实际调用返回的数据。
- **批量获取数据**。用 `query_projects(action="search", keyword="")` 一次性拉取全部项目，不要逐个 `get`。

---

## 可用工具速查

| 工具 / Resource | 用途 |
|---|---|
| `query_projects(action="search", keyword="", tag="")` | 获取全部或按标签过滤的项目列表 |
| `query_projects(action="get", project_id=...)` | 获取单个项目完整元数据（含 field_values） |
| `query_projects(action="count", tag=...)` | 统计项目数量 |
| `manage_libraries(action="get_fields")` | 获取全部字段定义 |
| `cabinet://library/info` | 库基本信息（总项目数、字段数） |
| `cabinet://library/stats` | 统计概览（标签分布） |
| `cabinet://tags` | 全部标签及使用计数 |

---

## 审核维度（按严重程度排序）

### 一、缺失描述（严重 ⚠️）

**判定**：`description_md` 为空或仅包含空白字符。

**操作**：
```
query_projects(action="search", keyword="")
→ 遍历返回结果，筛选 description_md 为空的项目
```

也可以对返回中的每个项目调 `get` 获取完整信息（description 在 search 结果中不返回）：
```
query_projects(action="get", project_id=15)
→ 检查返回的 description_md 字段
```

**报告**：`N 个项目缺少描述（占比 X%）`

---

### 二、缺失标签（中等 ⚠️）

**判定**：`tags` 数组为空。

**操作**：从 `query_projects(action="search")` 的返回中筛选 `tags` 为空的项目。

**报告**：`N 个项目没有任何标签（占比 X%）` + 列出项目 ID 和 title。

---

### 三、字段填充率（一般 ℹ️）

**判定**：库中自定义字段在各项目中的填充情况。

**操作**：
```
# 1. 获取全部字段
manage_libraries(action="get_fields")
→ [{id: 19, name: "作者", ...}, {id: 20, name: "出版日期", ...}]

# 2. 对每个项目获取完整元数据
query_projects(action="get", project_id=15)
→ 检查 field_values 中对应字段的 value 是否为空
```

**报告**：对每个自定义字段，统计空值项目数：
```
字段 "作者"：N/M 个项目未填（X%）
字段 "出版日期"：N/M 个项目未填（X%）
```

---

### 四、标签使用分布（参考 📊）

**操作**：
```
① cabinet://tags → 全部标签及使用计数
② query_projects(action="count") → 总项目数
```

**分析**：
- 是否有大量项目集中在少数标签（标签失衡）
- 是否有孤立的单标签（只被 1 个项目使用）
- 是否存在语义重复的标签（如 "NLP" 和 "自然语言处理" 同时存在）
- 是否存在可以按层级组织的扁平标签（如存在 "钢琴" "小提琴" "圆号" 三个独立标签，可以统一归到 "乐器/钢琴" "乐器/小提琴" "乐器/圆号" 层级下）

**报告**：概括标签分布是否健康，如有问题给出合并建议。

---

### 五、文件完整性（可选 🗂️）

**操作**：
```
query_projects(action="search", keyword="")
→ 对 file_count > 0 的项目调 manage_files(action="list", project_id=...)
→ 检查各文件的 missing 状态
```

**报告**：如有 `missing: true` 的文件（文件路径断开），列出涉及的项目。

---

## 输出格式

生成结构化的审核报告：

```
# 📊 元数据质量审核报告

## 总体概况
- 审核项目数：N
- 审核时间：YYYY-MM-DD

## 一、缺失描述 ⚠️
N 个项目缺少描述（占比 X%）：
- #15 "项目名" — 建议补充：xxx
- #23 "项目名" — 建议补充：xxx

## 二、缺失标签 ⚠️
N 个项目无标签（占比 X%）：
- #15 "项目名" — 建议标签：xxx（因为...）
- #23 "项目名" — 建议标签：xxx（因为...）

## 三、字段填充率 ℹ️
| 字段名 | 已填 | 未填 | 填充率 |
|--------|------|------|--------|
| 作者   | 30   | 12   | 71%    |
| 出版日期 | 25 | 17   | 60%    |

## 四、标签分布 📊
- 标签总数：M
- 前 5 热门标签：xxx（N 项目）、xxx（N 项目）...
- 单例标签（仅 1 个项目使用）：K 个
- 疑似重复标签：["NLP", "自然语言处理"] → 建议合并为 "学科领域/自然语言处理"
- 可层级组织的标签：["钢琴", "小提琴", "圆号"] → 建议归并为 "乐器/钢琴"、"乐器/小提琴"、"乐器/圆号"

## 五、文件完整性 🗂️（可选）
- {N} 个项目共 {M} 个文件的 link 已断开

## 总结建议
1. 优先处理：N 个缺描述项目
2. 建议处理：N 个缺标签项目
3. 可选：清理 K 个疑似重复标签
```

---

## 边界处理

| 场景 | 处理 |
|---|---|
| 库中没有项目 | 报告 "库中暂无项目，无需审核" |
| 库中没有自定义字段 | 跳过"字段填充率"维度 |
| 项目数 > 100 | 分页处理，每批 30-50 个项目做字段检查 |
| search 返回过慢 | 可改用 `cabinet://projects` Resource 获取摘要（再对缺元数据的逐条 get） |
