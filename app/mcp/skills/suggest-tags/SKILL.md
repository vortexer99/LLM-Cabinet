# 推荐标签

你的任务是为项目推荐合适的标签。**只做推荐，不自动应用**。用户确认前不调用任何写操作。

---

## 全局约束

- **只读操作**。不调用 manage_project(add_tag / remove_tag) 等写操作。
- **优先复用已有标签**。`cabinet://tags` 中现有的标签优先使用，创建新标签是最后手段。
- **标签格式统一**。标签使用 `分类/子分类` 层级格式（如 `学科领域/计算机科学`）。
- **给出理由**。每个推荐标签附一句话说明为什么适合。

---

## 可用工具速查

| 工具 / Resource | 用途 |
|---|---|
| `cabinet://tags` | 全部已有标签及使用计数 |
| `query_projects(action="search", keyword="", tag="")` | 搜索/列出项目 |
| `query_projects(action="get", project_id=...)` | 获取单个项目完整详情 |
| `manage_project(action="add_tag", project_id=..., tag=...)` | （仅供用户确认后使用） |

---

## 操作流程

### 第 1 步：了解可用标签

```
cabinet://tags
→ [
    {name: "学科领域/计算机科学", count: 18},
    {name: "学科领域/物理学", count: 12},
    {name: "文献类型/论文", count: 25},
    {name: "文献类型/代码", count: 5},
    {name: "阅读状态/未读", count: 30},
    ...
]
```

**按分类统计**：将标签按 `/` 前的顶级分类分组，便于了解库的标签体系结构。例如：
- `学科领域`：计算机科学(18)、物理学(12)、生物学(8)……
- `文献类型`：论文(25)、代码(5)、书籍(3)……
- `阅读状态`：未读(30)、在读(8)、已读(5)……
- `发表状态`：预印本(7)、已发表(15)……

---

### 第 2 步：获取目标项目

**如果指定了 `project_id`**：
```
query_projects(action="get", project_id=42)
→ {id: 42, title: "Attention Is All You Need", description_md: "...", tags: ["NLP"], field_values: {...}}
```

**如果未指定（`project_id` 为 0 或空）**：

列出全部缺少标签或标签不足的项目：
```
query_projects(action="search", keyword="")
→ 遍历结果，筛选 tags 数组为空或仅有 1 个标签的项目
```

优先处理**标签数为 0** 的项目；其次处理**标签数 ≤ 1** 的项目。

---

### 第 3 步：分析项目内容

对每个目标项目，从以下信息源推断合适标签：

| 信息源 | 提取内容 | 对应标签分类 |
|--------|----------|-------------|
| `title` | 核心主题、技术名称、论文标题关键词 | `学科领域/` |
| `description_md` | 详情的领域归属、方法类型、应用场景 | `学科领域/`、`项目类型/` |
| `field_values` | 如有 "作者" → 可能是论文；有 "DOI" → 学术文献 | `文献类型/` |
| 文件名（如有 file） | PDF → 论文；.py/.js → 代码；.zip → 数据集 | `文献类型/`、`项目类型/` |
| 已有 tags | 已有的层级前缀决定后续标签的层级 | 继承已有层级 |

**关键词 → 标签映射示例**：

| 项目标题/描述含有关键词 | 推荐标签 |
|---|---|
| transformer, attention, NLP, BERT, GPT, LLM | 学科领域/计算机科学, 学科领域/人工智能, 学科领域/自然语言处理 |
| quantum, entanglement, schrödinger, qubit | 学科领域/物理学, 学科领域/量子力学 |
| CRISPR, gene, protein, DNA, RNA | 学科领域/生物学, 学科领域/分子生物学 |
| CNN, ResNet, ImageNet, vision, detection | 学科领域/计算机科学, 学科领域/计算机视觉 |
| reinforcement, Q-learning, policy gradient | 学科领域/计算机科学, 学科领域/强化学习 |
| semiconductor, chip, CMOS, transistor | 学科领域/电子工程, 学科领域/半导体 |
| arXiv, DOI, et al., conference | 文献类型/论文 |
| github, repo, pip install, npm | 文献类型/代码, 项目类型/软件 |
| survey, review, comprehensive | 文献类型/综述 |
| dataset, benchmark, corpus | 项目类型/数据集 |
| tutorial, course, lecture | 文献类型/教程 |

---

### 第 4 步：推荐标签

对每个项目输出：

```
## #42 "Attention Is All You Need"

推荐标签：
- ✅ 学科领域/计算机科学（已有，18 项目使用）
  理由：NLP 经典论文，属于计算机科学
- ✅ 学科领域/自然语言处理（已有，9 项目使用）
  理由：提出 Transformer 架构，NLP 领域奠基性工作
- ✅ 文献类型/论文（已有，25 项目使用）
  理由：发表于 NeurIPS 2017
- ✅ 阅读状态/未读（已有，30 项目使用）
  理由：默认阅读状态
- 🆕 模型架构/Transformer（新建）
  理由：Transformer 已成为独立研究方向，现有标签中无此分类

是否全部应用？如有异议请告知调整。
```

**标签推荐规则**：
- `✅` 标记已有标签，附上使用计数
- `🆕` 标记建议新建的标签，说明为什么不能复用已有标签
- 每项目推荐 3-5 个标签为宜，不超过 8 个
- 标签格式统一为 `分类/子分类`，新建的也遵循此格式
- 如果项目的已有标签已经覆盖了推荐标签，不再重复推荐

---

### 第 5 步：交互确认

- 如果只有 1 个项目，直接展示推荐列表并询问是否应用
- 如果有多个项目，先展示汇总（"以下 N 个项目需要标签补充"），再逐个展示
- 用户说 "应用" 或 "确认" 后，才调用：
  ```
  manage_project(action="add_tag", project_id=42, tag="学科领域/计算机科学")
  manage_project(action="add_tag", project_id=42, tag="学科领域/自然语言处理")
  ...
  ```

---

## 标签体系设计原则

1. **层级清晰**：`顶级分类/子分类`，如 `学科领域/自然语言处理`。不超过 3 级。
2. **互斥且完备**：同一项目在不同顶级分类下各取一个标签（如同时属于 `学科领域/`、`文献类型/`、`阅读状态/`）。
3. **避免过度细分**：如果 `自然语言处理` 下只有 1-2 个项目，不要创建 `自然语言处理/文本分类`、`自然语言处理/机器翻译` 等价子标签。
4. **常见顶级分类**：
   - `学科领域/`：计算机科学、物理学、生物学、数学、电子工程……
   - `文献类型/`：论文、书籍、代码、数据集、报告、专利、教程……
   - `阅读状态/`：未读、在读、已读
   - `发表状态/`：预印本、已发表、已接收
   - `项目类型/`：软件、实验、课程、笔记

---

## 边界处理

| 场景 | 处理 |
|---|---|
| 库中没有任何标签 | 所有推荐都是 `🆕` 新建，建议先建立基本标签体系 |
| 项目已经有 5+ 标签 | 可能已经足够，只推荐明显缺失的维度 |
| 项目内容无法判断 | 描述太少或标题无意义 → 建议用户补充 description 后再推荐 |
| cabinet://tags 返回空 | 该库尚无标签体系，需从头建立 |
| 多个项目相似 | 用相同的标签体系保持一致性 |
