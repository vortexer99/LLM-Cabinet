# 工作流程

每条命令都显式指定同一个目标库；命令语法见 [commands.md](commands.md)。

## 整理新文件

1. 发现并选定目标库，读取 `library fields` 和 `library tags`，了解现有字段与分类。
2. 从用户指定的文件或目录发现待整理文件。按用户要求决定一文件一项目或分组；不要仅因目录相邻就合并。
3. 用 `projects search` 定位候选，再用 `projects get` / `files list` 判断是否属于同一项目。已有文件数量不是匹配依据。用户明确要求新建时无需先找旧项目。
4. 根据实际可读取的内容整理标题、描述、标签、字段。不能读取正文时说明依据的局限；不凭文件名臆造作者、DOI 等事实。尊重字段的 suggest_enabled 与 prompt_hint。
5. 在用户授权范围内使用 `--write projects create/update` 和 `files add`。先验证文件存在；创建成功后使用返回的项目 ID。逐次检查结果，创建成功但添加失败时报告已创建的项目，不重复创建。
6. `files add` 默认用 link，填写简洁中文 label。若用户需要实际复制入仓储，说明本命令不执行复制；不要把“登记 copy 路径”当作复制完成。
7. 汇总创建/更新项目、登记文件及失败项，并说明存储方式。

## 审核元数据

读取字段定义及项目列表，再检查用户指定范围的详情：空描述、缺失标签、启用建议的字段未填、明显重复或格式不一致。报告项目 ID、问题和建议。审核本身不写入；只有用户要求修复时才执行已明确的修改。

## 生成库概览

优先用 `library info/stats/tags` 得到项目总数、未分类数及标签分布。需要近期项目时读取搜索结果中的 updated_at。没有对应数据时不要宣称已统计文件正文、质量评分或字段填充率；必要时读取详情计算并说明统计范围。

## 推荐标签

先读取已有标签，再查看目标项目详情和可用文件信息，优先复用相同含义的标签及已有层级。用户只要求建议时列出候选与依据；要求应用时用 `projects add-tag`，避免用 update 的 tags 意外覆盖原标签。
