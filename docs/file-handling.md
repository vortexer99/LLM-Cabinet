## 1. 文件数据模型速览

理解下面这张表，后续所有任务都能对上号。

### 1.1 `files` 表关键列

| 列 | 含义 | 引入任务 |
|---|---|---|
| `path` | 文件路径：仓储模式存"相对库根的相对路径"，链接模式存"绝对路径" | 基础 |
| `is_relative` | `1`=📦仓储（库内副本）／`0`=🔗链接（指向外部原文件） | 基础 |
| `label` | 用户可填的备注名（如「中文版」「封面（截取自 PDF）」） | 基础 |
| `kind` | 类型：`pdf`/`image`/`video`/`other`… 决定预览方式 | 基础 |
| `ord` | 项目内排序 | 基础 |
| `missing` | 一致性检查标记：物理文件丢失时置 `1` | #14 |
| `subfolder` | **逻辑**子目录路径（POSIX，`""`=顶层），驱动文件表树形展示，与物理位置解耦 | #17 |
| `origin` | 文件来源：`user`=用户原始文件／`generated`=软件衍生物（封面快照等） | #30（规划中） |

### 1.2 两种存储模式

| 模式 | `is_relative` | 文件在哪 | 适用 |
|---|---|---|---|
| 📦 仓储 | `1` | 复制进 `library/project_<id>/` | 自包含、可整库备份/搬家 |
| 🔗 链接 | `0` | 留在用户原始位置，库里只存绝对路径 | 不想多占空间、文件由别处管理 |

### 1.3 封面（`projects.cover_file_id`）

封面**不是单独的数据**，而是指向该项目某个 `files` 行的指针。它有两种来源：

- **用户图片**：直接把某张图片文件设为封面（只动指针，`origin='user'`）。
- **软件生成快照**：截 PDF 首页 / 视频帧 / 剪贴板图 → 生成 `__cover_*.png` 落进库，新增一条 `files` 行（`origin='generated'`）。

### 2.1 已完成的地基

#### [#01 文件表列自定义 + 存储方式列](../tasks/01-files-table-customization.md) ✅
- **做什么**：文件表的列可显示/隐藏、列宽可调；新增只读的「存储方式」列（📦/🔗）。
- **目标**：让用户按需裁剪文件表视图，并一眼看出每个文件是库内副本还是外部链接。

#### [#02 文件列表独立窗口](../tasks/02-files-table-detach-window.md) ✅
- **做什么**：把文件列表从主窗口拆出，可独立成一个窗口。
- **目标**：文件多时给更大的浏览/操作空间，不挤占主界面。

#### [#09 项目导出（基础版）](../tasks/09-project-export-basic.md) ✅
- **做什么**：把单个项目导出成目录包（`project.json` + `files.json` + `README.md` + `files/`）。
- **目标**：项目可被人类检视、可分享/备份，并定义出后续导入识别的标准包结构。

#### [#10 文件夹批量导入](../tasks/10-folder-batch-import.md) ✅
- **做什么**：把若干文件夹批量导入为项目；识别 `project.json` 恢复元数据、按 `field_name` 匹配字段、提供未匹配字段策略（创建/追加描述/忽略）。
- **目标**：批量入库；并让 #09 导出的包能被重新导入，初步形成闭环。

#### [#17 子文件夹导入修复 + 文件表树形](../tasks/17-subfolder-import-and-tree-view.md) ✅
- **做什么**：新增 `files.subfolder`（schema v6→v7），文件表由扁平表改为 `QTreeWidget` 树形；逻辑目录由数据库驱动，与物理存储解耦。
- **目标**：保留并展示用户的目录层级，是后续「折叠」「目录树还原」的数据基础。

### 2.2 规划中（建议按此顺序推进）

#### [#30 文件来源标记 `files.origin`](../tasks/30-file-origin-marker.md) · 待做 · 建议最先做
- **做什么**：给 `files` 表加 `origin` 列（schema v7→v8，`user`/`generated`）；封面快照生成时打 `generated`；历史 `__cover_*.png` 行回填。
- **目标**：在数据层正式区分「用户原始数据」与「软件衍生数据」，让导出/导入、一致性统计、UI 折叠都能统一消费。
- **为什么先做**：它是 #28（导出要忠实保留来源）和 #04（折叠衍生文件）共同的地基，且改动最小、最独立。

#### [#28 导出/导入闭环](../tasks/28-export-structure-option.md) · 待做
- **做什么**：扩展导出选项（独立包/仅元数据、目录/ZIP、保留结构/拍平、内容选项）；批量导出多项目；在现有导入器上补 ZIP 解包、封面 id 重映射、拍平结构的目录树还原、`origin` 还原。
- **目标**：把「导出 → 修改/备份 → 再导入」做成完整可靠的闭环，且衍生数据（封面、来源）在往返中不丢失。
- **依赖**：强依赖 #17 #09 #10 **#30**；软依赖 #25（项目多选，用于批量导出入口）。

#### [#04 项目内系统/衍生文件折叠（二态视图）](../tasks/04-project-system-files-folding.md) · 待做（澄清完毕）
- **做什么**：文件表上方加 `[ 👤 仅用户文件 | 🌐 显示所有 ]` toggle，按 `origin` 筛选；默认隐藏 `generated`（如封面快照）；状态按项目持久化。
- **目标**：让文件列表聚焦用户真正添加的内容，自动生成的封面快照等衍生物不再污染主列表。
- **依赖**：强依赖 #30（消费 `files.origin`）；与 #17 树形、#31b 扁平视图正交。

#### [#29 文件存储位置管理](../tasks/29-file-storage-location-management.md) · 待做 · 可独立推进
- **做什么**：文件表右键新增 5 类操作——T1 链接转仓储 / T2 移动到新位置 / T3a 重关联到外部文件（修复 missing） / T3b 替换链接目标（单选） / T3c 文件夹粒度批量入口（聚合 T1/T2/T3a）。
- **目标**：让用户自由调整单个/多个文件的物理存放与存储模式（🔗↔📦、跨盘搬家、修补失效链接、换底本），区别于库级整体迁移。
- **依赖**：依赖 #17（FileItem/树形）+ #14 T1（missing 标记）+ 复用 #09/#10 的进度对话框；协同 #32（执行前调用 `find_references` 做多引用警告）。

#### [#31a 树形视图：拖动改位置 + 同级排序 + 新建文件夹 + F2 重命名](../tasks/31a-files-tree-interactions.md) · 待做 · 可独立推进
- **做什么**：树形视图下点列头排序（同级文件，文件夹恒在前）；拖动改 ord / 跨 subfolder 移动；新建空 subfolder（`explicit_subfolders` 持久化）；F2 重命名 label / Shift+F2 物理文件名 / 文件夹节点 F2 改 subfolder。
- **目标**：让项目内文件的浏览与整理更顺手，把树形视图打磨到资源管理器水准。
- **依赖**：依赖 #17 的树形控件；联动 #02（独立窗口复用同一控件）；触及 `repository.update_file` 对 `subfolder` 的支持；协同 #32（物理改名跨项目引用警告）。

#### [#31b 扁平视图模式 + 大小/时间列 + 列任意排序](../tasks/31b-files-table-flat-view.md) · 待做 · 可独立推进
- **做什么**：新增视图模式切换（🌲 树形 ↔ 📋 扁平）；扁平视图下用 Qt 原生 `setSortingEnabled` 支持任意列排序；新增"大小""添加时间"两列（延迟 stat 缓存）。
- **目标**：让"找最大文件 / 看最近加的文件"这类跨 subfolder 浏览任务有合适的视图。
- **依赖**：依赖 #17；协同 #31a（两种视图正交，列定义共享）。

#### [#32 跨项目链接引用](../tasks/32-cross-project-file-reference.md) · 待做
- **做什么**：T1 加"引用其他项目的文件"入口（项目+文件选择器 + 落库为 🔗 链接，新行独立元数据）；T2 删除/移动文件 / 删除项目时弹"多引用警告" + #14 一致性检查报告追加"跨项目引用统计"。
- **目标**：让同一物理文件可被多项目共享（最小方案：路径共享 + 删除护栏），不引入新表、零 schema 改动。
- **依赖**：强依赖 #17 + #14 T1 + #29（T1/T2/T3a/T3b 执行前要调 `find_references`）。

## 3. 推荐执行顺序（一句话版）

1. **#30**（来源标记，地基，最小）→
2. **#28**（导出/导入闭环，消费 #30）与 **#04**（折叠二态视图，消费 #30）可并行 →
3. **#29**（文件位置管理 T1/T2/T3a/T3b/T3c）→
4. **#31a**（树形交互）与 **#31b**（扁平视图）相对独立，可并行；视图模式切换由 #31b 落地 →
5. **#32**（跨项目引用）放最后：T1 独立，T2 的多引用警告需要在 #29 各执行流程里插入检查点。

> 任何涉及 `files` 表 schema 的任务（如 #30 的 v7→v8）都必须按 [`migrations.md`](./migrations.md) 的流程走：bump `SCHEMA_VERSION` + 写幂等迁移 + 注册 + 自动备份 + 更新 `CHANGELOG.md` + selftest 覆盖。
