# 04 · 项目内系统/配置文件折叠

`TODO.md → 📦 项目 & 文件管理` 第 2 条

## 目标
项目里被识别为"应用运行所需配置文件"的文件单独折叠到分组，避免污染主列表。

## ❓ 需求澄清（开工前必须确认）

当前 LLM Cabinet 自身没有"项目内的配置文件"概念，存在三种可能解读：

1. **衍生文件**：指 `__cover_*.png`（自动截取的封面）这类应用生成的辅助资源，应折叠不让用户误删
2. **按扩展名自动分类**：`.json` / `.toml` / `.ini` 等配置类后缀的用户文件自动归到"配置区"
3. **手动标记**：给每个 file 加 `category` 字段（content / config / asset / system），用户可在文件表里改

不同解读对应不同实现：
| 选项 | 数据迁移 | 自动化程度 | 误判风险 |
|---|---|---|---|
| 1 衍生文件 | 无（按 label 或文件名前缀识别） | 高 | 低 |
| 2 按扩展名 | 无 | 高 | 中（用户可能就是想管理 .json） |
| 3 手动标记 | 需加列 | 低 | 无 |

**建议先做选项 1**：把 `label="封面（来自剪切板）"` / `label="封面（截取自 PDF）"` 等自动归到"📎 衍生文件"折叠组，默认折叠。

## 实现要点（按选项 1 估算）
- 文件列表渲染时分组：
  - 用 `QTreeWidget` 替代 `QTableWidget`，或在 `QTableView` 上用自定义代理画分组行
  - 简单实现：表头插一行 `📎 衍生文件 (N) ▾`，点击折叠/展开
- 识别规则：`label LIKE '封面（%）'` 或 `path LIKE '%__cover_%'`
- 折叠状态持久化到 settings

## 依赖
- 无强依赖
- 与 T1（文件表自定义）共存：折叠分组属于"显示策略"，不影响列设置

## 风险
- QTableWidget 不原生支持分组行，方案上要选；可能要重构成 QTreeWidget
