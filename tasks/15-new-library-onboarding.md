* **D1 db 创建时机**：**最后一步建**（晚建）。第 1~4 页只收集表单数据；点最终
  「创建库」才一次性 `mark_as_library + connect db + _seed_fields + 加可选字段
  + 写库描述 + 迁移 API`。**好处**：用户中途取消零副作用，不需要"清理 vs 保留"
  二次确认。
* **D2 默认列可见性**：**沿用 task 卡原方案** — 新库的「描述 / 标签」字段
  `visible=0`（理由：多行文本占主列表空间；标签筛选已经有左侧标签树）。

* **D3 API 迁移 keys 两档**：第 4 页提供单选

  - **全部迁移**：上述 + `llm_default_provider` + `llm_default_language` + `wizard_max_rounds`
* **D4 横幅消失条件**：用一次性标志 `library_first_run_dismissed`：用户**做过任何
  动作**（运行助手成功一次 / 自己加过字段 / 添加过项目 / 主动点过"不再显示"）→
  永久不再显示，避免"项目数回到 0 时横幅复活"的诡异体验。**不**额外引入会话级
  隐藏 key — 用户只有一种"不想看"的意图，单 key 就够。
* ~~**D5 T3 默认位置路径不补描述**~~（已废弃 — Welcome 不再有"使用默认位置"选项；

## 目标

把"新建库"从一次性技术操作升级为**带入门引导的 onboarding 流程**，让用户在建完库的
那一刻就知道："这个库是干什么的"、"我有哪些字段"、"接下来该做什么"。

不追求复杂模板系统，先把现有功能（库描述 + 字段表 + 库字段设计助手）按一个连贯的
Wizard 串起来。

设置新库默认按列表展示。

### 实现要点

- 复用 `app/db.py:DEFAULT_FIELDS` 当前注释掉的 4 项；做成一个 `OPTIONAL_DEFAULT_FIELDS`
  常量，把这些恢复为可选项（不是被注释掉的死代码）。`projects` 表的 `author / date /
  source_url / rating` 列保持不动（已经存在，不变更 schema）
- `_lib_new()` 改为弹一个 `QDialog + QStackedWidget` 多页向导（参考
  `app/ui/wizards/library_init.py:LibraryInitWizard` 的 PAGE_INTRO/SCENARIO/PREVIEW 风格）；
  页数 3 页或 4 页按 `cabinet_config.list_handles()` 是否有其它库决定
- **库创建时机（D1）**：3~4 页全部只收集表单数据到 wizard state；用户在最后一页
  点「创建库」才一次性执行：
  1. `mark_as_library(root)` + `lib_subdir.mkdir(...)` + `connect(db_path)`
  2. `_seed_fields` 自动种 标题/描述/标签
  3. 按用户在第 3 页对**必有字段**的勾选，`UPDATE fields SET visible=? WHERE key IN ('description','tags')`
     （标题恒可见，UI 也禁用了它的复选框）
  4. 按用户在第 3 页对**可选默认字段**的勾选，追加 `INSERT INTO fields(...)` 行（含其
     `列表显示` 复选框对应的 `visible`）
  5. 写 `repo.set_setting("library_description", text)`
  5b. 写 `repo.set_setting("default_view_mode", "list")` — 新建库默认列表视图
      （理由：用户刚配好"列表显示"复选框，新库首屏直接看到这些列更直观；既有库
      的全局 fallback 仍是 `"grid"`，不动）
  6. 若第 4 页选了源库 → 调 `import_settings_from_other_db` 读出 keys，逐项
     `repo.set_setting` 写入新库
  7. `cabinet_config.touch + save + restart`
  上述步骤任何一步抛错 → 整体回滚（`shutil.rmtree(root)` 清掉刚 mark 的目录）
  并提示用户；用户可重试或退出向导。**取消**（任意非最后一页点 X / 取消按钮）
  零副作用：什么都没做就是关闭对话框。
- 库描述：见上 step 5
- 默认字段：见上 step 3 / step 4
- **默认列可见性调整（D2）**：`_seed_fields` 当前给三保护字段都种 `visible=1`；改为
  - 标题：`visible=1`（强制；`is_title` 已经在 UI 层强制可见）
  - 描述：**`visible=0`**（默认隐藏 — 多行文本在主列表里太占空间，仅在项目编辑对话框显示）
  - 标签：**`visible=0`**（默认隐藏 — 标签筛选已经有左侧标签树，列表里再列一遍冗余）
  - **必有字段的可见性也面向用户开放**：第 3 页里描述 / 标签自带「列表显示」复选框
    （默认未勾选 = D2 默认隐藏；勾上则建库时直接 `visible=1`）；建库后任何时候都可
    在「设置 → 字段」里再改。标题的复选框被禁用，UI 也不允许隐藏。
  - 可选默认字段（作者/日期/评分/来源）：用户可在第 3 页同行的"列表显示"复选框单独控制
    （默认全开，因为它们都是单行小内容，列表里展示有用）
  - 注意：本变更**只影响新建库**；既有库的 `visible` 不动（避免回归）
- **从其它库迁移 API 配置（第 4 页）**：
  - 显示条件：`len(cabinet_config.list_handles()) >= 1`（首次建库无源可迁移则跳过此页）
  - **三档单选**置于"从哪个库迁移？"上方：**不迁移** / 仅迁移 LLM 配置（默认）/ 全部迁移；
    选「不迁移」时下方下拉 `setEnabled(False)`
  - 源库下拉：默认源 = `cabinet_config.default()` 指向的库；按"最近打开时间"倒序列出全部已知库；
    末项 `📂 浏览其它库目录...` 弹 `getExistingDirectory`，要求目录含 `.llm-cabinet`
    标记（`is_library_dir`）；选中的非已知库目录会**插入到下拉里**便于复选 / 修改主意
  - 复用现有 `app/cabinet.py:import_settings_from_other_db(...)`（task #08 已实现，
    也供「库 → 从其它库导入 API 配置...」菜单使用）；新建库 step 6 调用
  - **迁移内容两档（D3）keys**：
    - **仅迁移 LLM 配置**（默认）：keys = `["llm_config"]`
    - **全部迁移**：keys = `["llm_config", "llm_default_provider", "llm_default_language", "wizard_max_rounds"]`
  - 失败兜底：源库 db 损坏 / 解锁失败 → 弹错误提示但**不阻塞建库**，仅跳过 step 6
  - **工具栏「库 → 从其它库导入 API 配置...」也走同一交互范式**（近期库下拉 +

## T2：首次进入引导横幅

### 入口

主窗口右侧主区域顶部（项目列表上方），有条件显示一条**dismissible 横幅卡片**：

显示条件 — **全部满足**才显示：
- `repo.get_setting("library_first_run_dismissed", "0") != "1"`（D4 一次性标志；
  一旦置 1，永久隐藏，下方"消失时机"细述）
- `repo.count_projects_total() == 0`（库里没项目）
- `repo.count_user_added_fields() == 0`（用户没自己加过字段；新加 helper，
  实现 = `len([f for f in fields if not f.is_system and f.id not in seeded_ids])`，
  或更简单：`fields` 表里超过 `_seed_fields` 默认 3 条的就算）

> 设计简化：原本想做"会话级隐藏 `hide_first_run_banner`" + "永久隐藏
> `library_first_run_dismissed`" 两个 key；后来发现"我不想再看到这横幅"几乎
> 总是用户的最终意图，没有"我只是当次不想看，下次还想看"的合理用例 → 合并为
> 单 key `library_first_run_dismissed`，UI 上的「不再显示 ✕」直接写它。

### D4 一次性标志触发时机

下列任一动作发生后立刻 `repo.set_setting("library_first_run_dismissed", "1")`：

- 用户在「库字段设计助手」里成功"应用"过一次（已有 `library_init_wizard_done=1`，
  本身就是兜底；额外再写 D4 标志保持冗余）
- 用户在「设置 → 字段」里**主动添加**了任何非系统字段（hook 在
  `Repository.add_field` 上层 UI 入口）
- 用户成功创建第一个项目（hook 在 `_drop_create_project` / 项目导入 / 手动
  新建项目对话框确认时）
- 用户在横幅上点「不再显示 ✕」

D4 标志一旦置 1，永久不再显示横幅 — 即便用户后来删光所有项目让计数回到 0。

### 横幅内容

```
┌──────────────────────────────────────────────────────────────┐
│ 🎉 新库已创建！下一步可以…                                     │
│                                                              │
│  • 让 AI 根据你的描述帮你规划字段        [🪄 库字段设计助手]    │
│  • 自己手动加几个字段                    [📋 设置 → 字段]      │
│  • 把第一份资料拖到项目列表底部“创建项目区”试试                  │
│                                                              │
│                                            [ 不再显示 ✕ ]    │
└──────────────────────────────────────────────────────────────┘
```

### 行为

- 「🪄 库字段设计助手」→ 等同 `工具 → LLM 助手 → 库字段设计助手`
- 「📋 设置 → 字段」→ 打开设置对话框并跳到字段页（需要 SettingsDialog 暴露
  `set_active_category("字段")`）
- 「不再显示 ✕」→ `repo.set_setting("library_first_run_dismissed", "1")`，
  立即隐藏横幅 **且**永久不再出现（即 D4 一次性标志的用户主动入口）
- 用户运行过库字段设计助手且实际应用了 → 横幅自动消失（依赖
  `library_init_wizard_done=1`，已存在；同时由 D4 hook 写
  `library_first_run_dismissed=1`，双重兜底）
- 用户导入第一个项目后 → 横幅自动消失（`count_projects_total() > 0`，同时 D4 hook 置位）

### 实现要点

## T4（远期）：库模板系统

### 思路

内置一套"场景包"，每个包含：
- 库描述模板（用户入参补全）
- 字段集（含每字段的 `prompt_hint`）
- 标签分类策略（写入「标签」字段的 hint）

模板 manifest 存为 `app/templates/<id>.json`：

```json
{
  "id": "academic_papers",
  "title": "学术论文库",
  "icon": "📚",
  "description": "管理你阅读 / 撰写的学术论文…",
  "library_description_template": "你管理一份学术论文库…",
  "fields": [
    {"name": "标题", "type": "text", "prompt_hint": "..."},
    {"name": "DOI", "type": "url", "prompt_hint": "..."},
    {"name": "出版年份", "type": "date", "prompt_hint": "..."},
    {"name": "引用次数", "type": "number", "prompt_hint": "..."}
    ...
  ]
}
```

### 内置模板（首批）

- 📚 学术论文库
- 📖 小说 / 漫画追番
- 🍳 菜谱
- 💻 代码片段
- 🎮 游戏素材
- 📰 新闻 / 资讯归档
- 🆓 空白库（不预设字段，等用户自己加 / 跑助手）

### 入口

T1 第 3 页加一行 "或从模板新建：[选模板... ▼]" 下拉；选中后跳过第 3 页的字段勾选，
直接用模板的字段集。

### 自检（task #15 T4）

- 模板 manifest 解析（合法 / 缺字段 / 字段类型不合法 → 拒绝）
