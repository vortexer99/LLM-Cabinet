# Task 51 — 标签筛选刷新与封面加载性能优化

- 来源：用户反馈切换标签筛选卡顿。
- 状态：✅ 完成，2026-11-16（Unreleased）。
- 约束：不读取用户数据库；测试仅使用显式临时库与合成记录、图片。无需 schema 迁移。

## 实现

- 标签、文件类型和搜索筛选使用轻量刷新。SQLite 本连接累计写入数、外部提交版本及 Repository 身份共同判断是否可以复用侧栏；数据变化和显式刷新走完整路径。
- 不再对命中项目逐个预读封面，ProjectModel 在卡片请求封面时加载，缓存成功和空值；更换数据、局部更新时正确失效。列表模式不读取封面。
- 文件计数限定命中项目，按 900 个 ID 分批以兼容绑定参数上限，空结果无文件查询。
- 模型重置与恢复选择期间阻断中间选择信号，避免先清空再加载预览。仅切筛选且原项目仍命中时保留文件列表、当前文件和播放状态。

## 验证

- `gui_filter_performance.py`：25 项通过，覆盖刷新工作量、失效边界、选择和空结果。
- `gui_project_cover_loading.py`：42 项通过。
- 主窗口回归 58、文件筛选 98、收藏／随便看看 56、视频封面与播放保持 360 项通过；修改的 Python 文件编译通过。
- 同机 Qt offscreen、1200 项目／18000 文件／200 标签，四次标签切换（含一轮绘制）的中位耗时：优化前 3361.9ms，优化后约 31ms；封面加载调用从 4800 次降至 64 次。该结果来自合成测试库，不代表所有真实库和硬盘的耗时；以行为断言而非绝对耗时作为通过标准。

## 边界

- 可见卡片的首次图片解码仍在 GUI 线程执行；项目查询仍为完整命中结果。极慢外部磁盘或更大数据量可另行评估后台解码／分页。
