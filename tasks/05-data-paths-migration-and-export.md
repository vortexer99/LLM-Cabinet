## T6 · 数据路径自定义并迁移  · ⛔ 已弃用（被 #08 取代）

**来源**：`TODO.md → 📦 项目 & 文件管理` 第 3 条

> 以下设计内容仅作历史保留，**不再计划实现**。理由见上方更新说明。

### 目标
设置里允许选新位置，并提供"迁移现有数据"功能。当前 DB 与库目录路径硬编码到 `%APPDATA%/LLMCabinet/`，用户无法迁到大容量盘。

### 实现要点
- 设置 → 项目库 页加两个"选择目录"按钮：
  - 数据库目录（含 `cabinet.db`）
  - 库目录（`library/`，已有路径展示，加"选择新位置 + 迁移"按钮）
- 迁移流程：
  1. 弹确认对话框，列出要移动的文件总大小
  2. 关闭 LLM worker 与 DB 连接
  3. 复制（不剪切）到新位置 → 校验完整性 → 删除旧文件
  4. 写入新路径到 `settings` 表 + 更新 `library_root` 引用
  5. 重新连接 DB 与重启 LLM worker
- 迁移失败要可回滚：保留旧文件直到全部校验通过
- 进度条：按文件计数

### 风险
- 应用还在打开时迁移数据库有锁问题：必须先 `conn.close()`，新连接打开新路径
- 路径切换后 `is_relative=True` 的文件能否定位：`library_root` 也跟着迁过去，相对路径不变，OK
- 用户中途取消：保证旧数据完整

## T7 · 项目导入导出

**来源**：`TODO.md → 📦 项目 & 文件管理` 第 4 条

### 目标
把项目（含元数据 + 文件）导出为标准包，方便分享或备份。反向能导入 ZIP 重建项目。

### 实现要点
- **导出**：
  - 单个 ZIP，结构：
    ```
    project.json     # 元数据 + 字段值 + 标签 + 字段定义 snapshot
    files/           # 所有附属文件
    files_map.json   # files 表的记录数组（path / label / kind / is_relative）
    ```
  - 多选项目批量导出：每个项目一个 zip，或合并到一个 zip 带子目录
- **导入**：
  - 解析 zip → 写入新 project_id（避免冲突）
  - 文件统一用 `copy` 模式落到库目录
  - 字段定义按 key 映射到当前库；新字段名相同的复用，否则按"用户字段"新建
- 入口：菜单 → 文件 → 导出选中项目 / 导入项目包
- 多选优先按当前选中行；右键菜单也加入口

### 风险
- 字段映射歧义：导出库 A 的"作者"字段 → 导入到库 B 时如果同名但类型不同，怎么办？
  - 方案：优先按 key（系统字段）对齐；用户字段按 name 找，若 type 冲突则插入为带后缀的新字段
- 大文件：用流式写入避免内存爆

- 可抽出 `_run_with_progress(steps_iter, on_error_rollback)` 复用
