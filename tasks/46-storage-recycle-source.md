# 46 · 仓储入库后回收原文件

**工作量**：S
**优先级**：P1
**状态**：✅ 完成（2026-11-15，Unreleased）

## 来源与目标

用户要求添加库级设置：仓储模式存入后，将原文件移入回收站，并明确文件夹处理方式。

## 实现与约束

- `storage_recycle_source` 使用字符串 `1` / `0`，默认关闭。仅影响后续仓储导入和链接转仓储，不补处理历史文件。
- 添加文件、拖放新建/加入项目、文件夹批量导入、单文件/文件夹/整个项目转仓储统一遵守该偏好。
- 复制前记录源文件状态；复制成功且文件记录提交后再回收。复制失败、落库失败或取消时未完成的文件保留。
- 只回收文件，不删除目录：原目录（包括空文件夹）、未导入/过滤文件、ZIP 解包导入的原包保留。解压临时目录仍走原清理机制。
- 同源候选去重；本库仍有链接记录引用、源位于当前仓库内、源在复制期间改变、目标副本或已提交记录不匹配时保留源并提示。
- 新功能调用 `move_to_trash(..., allow_delete=False)`：回收站不可用时保留原文件，不回退硬删除；其它已有调用默认行为不变。
- 原文件处理失败不改变入库成功计数，批量汇总提示；设置页、导入对话框和转仓储确认框说明当前行为。
- GUI 的文件检查及回收在后台执行，提供进度和取消；取消只保留尚未回收的原文件，不撤销已入库副本。主线程预读数据库状态，后台不跨线程访问 SQLite；批量项目全部落库后统一去重回收。
- 不改变 schema；只使用独立临时库、自造文件和模拟回收目录验证，不访问用户数据库。
