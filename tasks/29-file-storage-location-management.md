## 目标

给文件表加四类"文件存储位置"操作，覆盖用户实际诉求：

1. **链接转仓储**：把🔗链接模式的外部文件**直接复制**进库，转成📦仓储，从此自包含、不依赖外部路径。
2. **移动文件到新位置**：把文件物理搬到用户指定目录，并更新数据库里的路径引用（典型场景：把项目文件从 A 盘挪到 B 盘）。
3. **重关联到外部文件**：库内副本丢失 / 链接失效时，让用户指定一个外部文件作为新的物理来源——**不搬文件，只改 path/is_relative**。修复 missing 文件的常见诉求。
4. **替换链接目标**：把🔗链接行的指向换成另一个文件（用户更新了外部文件、想换底本等）。

## T1 · 链接转仓储（直接复制）

### 入口

文件表右键菜单新增 **📦 转为仓储文件**：
- 选中**单个**🔗链接文件 → 该项
- 选中**多个**（含 🔗 与 📦 混选）→ 同样显示，执行时只处理其中的 🔗 文件，📦 文件跳过（已是仓储）
- 项目级（可选）：在项目右键加「📦 全部转为仓储」，把该项目所有 🔗 文件一次性转换

### 执行流程（每个文件）

1. `abs_src = library.resolve(f.path, is_relative=False)`（链接文件的原绝对路径）
2. 若 `abs_src` 不存在 → 跳过 + 记一条警告（复用 #14 失效检测的提示口径）
3. `rel = library.import_copy(f.project_id, abs_src)`（复制进库，自动处理同名）
4. `f.path = rel; f.is_relative = True` → `repo.update_file(f)`
5. ⚠️ **不删除原外部文件**（复制语义，最安全；用户原文件原封不动）
6. 进度回调 `(done, total, name)`，UI 进度对话框驱动

### 完成反馈

```
转换完成：
✅ 已复制到库内：5 个
⏭ 已是仓储、跳过：2 个
⚠ 原文件找不到、跳过：1 个
```

- 失败/跳过项列清单，文案用普通用户能懂的话（不用"落库""持久化"等黑话）。

## T2 · 移动文件到新位置

### 入口

文件表右键菜单新增 **📂 移动文件到…**（支持单选 / 多选）。

### 行为按存储方式分流

| 文件类型 | 移动语义 | 结果 |
|---|---|---|
| 🔗 链接（外部） | 把外部文件**物理移动**到用户选的新目录 | `path` 改成新绝对路径，仍是 🔗 链接 |
| 📦 仓储（库内） | 把库内副本**移出库**到新目录 | 文件离开 `library/`，转成 🔗 链接（`path`=新绝对路径，`is_relative=False`） |

> 仓储文件"移动到库外"本质就是退化为链接——这是合理且唯一自洽的语义；若用户只想在库内整理，那是 subfolder（逻辑目录，task #17）的事，不在本卡。

### 执行流程（每个文件）

1. 选目标目录（`QFileDialog.getExistingDirectory`）
2. `abs_src = library.resolve(f.path, f.is_relative)`
3. 目标 `dst = 新目录 / abs_src.name`，同名冲突自动加 `_1/_2`（复用 `import_copy` 的命名策略，抽成公用函数）
4. `shutil.move(abs_src, dst)`
5. 📦仓储文件：移动成功后无需再 `remove_relative`（move 已搬走）；🔗链接文件同理
6. `f.path = str(dst.resolve()); f.is_relative = False` → `repo.update_file(f)`
7. 失败（权限/跨盘/占用）→ 跳过该文件 + 警告，不影响其它文件

### 风险

- **跨盘移动**：`shutil.move` 跨盘时是"复制+删除"，大文件慢 → 进度对话框按文件计数。
- **移动后封面**：file id 不变，`cover_file_id` 自动跟随，无需处理。
- **部分失败**：逐文件独立处理，单个失败不回滚已成功的（与 #09/#10 的"尽力而为 + 汇总警告"一致）。

## T3a · 重关联到外部文件（修复 missing）

### 场景

- 库内文件被外部程序删了（或备份恢复时少了某些文件） → 文件被 #14 一致性检查打了 `missing=1`
- 链接文件的原绝对路径失效（文件被用户搬家了）
- 用户重新整理过文件夹，想把多个 missing 文件一次性指向新位置

### 入口

- 文件表右键菜单 **🔧 重关联到外部文件…**（单选/多选都可见，但仅对**含失效项**的选择有意义）
- 一致性检查报告（#14）里的失效清单 → 行级"重关联"快捷入口

### 交互（多选模式）

1. 用户选 N 个文件（不要求全部 missing；非 missing 的执行时跳过 + 提示）
2. 选**一个外部目录** `dst_dir`（`QFileDialog.getExistingDirectory`）
3. 程序按"原文件名"在 `dst_dir` 一层扫描（不递归，避免歧义）：
   - 找到唯一匹配 → 改 `path=str(dst_dir / name)`, `is_relative=False`, 清 `missing`
   - 找不到 → 跳过 + 警告"在 dst_dir 未找到 <name>"
   - 找到多个（不应该，目录里单层不会重名，留作健壮性）→ 跳过 + 警告
4. 反馈：`✅ 重关联 X 个 / ⏭ 跳过 Y 个 / ⚠ 未找到 Z 个`

### 交互（单选模式）

跳过"按文件名扫描"，直接 `QFileDialog.getOpenFileName` 让用户选具体的目标文件 → 改 path → 清 missing。
本质上等同于 T3b，但对 missing 文件的语义更明确（"修复"而非"替换"）。

### 实现要点

- **不搬文件**：T3a 的语义是"告诉数据库这个文件现在在哪"，物理文件用户自己摆好。
- **不要求文件存在**：用户选的目标路径若仍不存在，给警告但允许（"修复"应该宽松，可能用户是先改路径再放文件）。
- **清 `missing` 标记**：成功改 path 后 `repo.set_file_missing(fid, False)`。
- **多选时全部转链接模式**：T3a 后文件统一是 🔗 链接（外部）。如果用户想把它再变回📦仓储，再走一次 T1。
- **跨项目引用警告**（#32 完成后）：T3a 改 path 会让其他项目原本指向同一旧路径的引用变孤儿——但**重关联的本意就是修一个 path**，旧 path 失效是问题前置条件，所以跨项目引用清单作为提示，不拦截。

## T3b · 替换链接目标（单选）

### 场景

- 用户更新了外部文件版本（"中文版.pdf" 换成新译本）
- 链接挂错文件了，想换成另一个

### 入口

文件表右键菜单 **🔄 替换链接目标…**：
- **仅单选 🔗 链接文件时可见**（多选 / 📦 仓储不显示）
- 选 📦 仓储文件想"替换为外部链接"的语义太怪 —— 应该走 T2"移动到外部"

### 交互

1. `QFileDialog.getOpenFileName` 选目标文件
2. 改 `path=str(target)`, `is_relative=False`（仍是链接）
3. 不改 `label/kind/subfolder/ord/origin`（其他元数据完全保留）
4. 反馈："已替换为 <new_path>"

### 实现要点

- **强制单选**：右键菜单在多选时直接隐藏该项。理由：把 N 个文件都替换为同一个目标毫无意义。
- **kind 不自动改**：即使目标文件扩展名不同，也保留原 kind（用户可手动改）。理由：自动改 kind 会让缩略图/预览突然变样，用户难调试。

## T3c · 文件夹粒度入口

### 场景

按 task #17 的设计，库里没有"文件夹实体"，subfolder 是 UI 上的虚拟分组节点。但用户在文件夹节点上右键的诉求是真实的——"把整个章节文件夹搬到 D 盘""把整个 subfolder 转仓储"。

### 入口

文件表里 📁 subfolder 节点右键菜单：
- [x] **📦 整个文件夹转仓储**（聚合 T1，对该 subfolder 下所有 🔗 文件批量执行）
- [x] **📂 整个文件夹移到…**（聚合 T2，对该 subfolder 下所有文件批量执行）
- [x] **🔧 整个文件夹重关联到…**（聚合 T3a，对该 subfolder 下所有 missing 文件批量执行）

**不提供** "整个文件夹替换链接目标"——T3b 单选语义在文件夹级别没有意义。

### 实现要点

- 完全复用 T1/T2/T3a 的批处理逻辑，只是预先收集 `[f for f in files if f.subfolder == clicked_subfolder]` 作为输入。
- 进度对话框文案改为"<文件夹名>: X/Y"。
- 反馈对话框沿用各操作的现有格式。

> ✅ 已完成：主窗口目录节点右键菜单接入 T3c；文件范围由 `Repository.list_files_under_subfolder()` 统一收集，包含子层级并支持 `missing_only`。

## 校验

### T1 链接转仓储
- [ ] 右键单个🔗文件「转为仓储」→ 文件出现在 `library/project_N/`，文件表该行变 📦
- [ ] 原外部文件**仍在原位**（未被删除）

- [ ] 转换后封面图（若该文件是封面）仍正常显示
- [ ] 同名文件转入同项目 → 自动加 `_1` 不覆盖

### T2 移动文件
- [ ] 移动🔗链接文件 → 物理文件到新目录，`path` 更新，仍是🔗
- [ ] 移动📦仓储文件 → 文件离开 `library/`，文件表该行变🔗，`path` 指向新位置

- [ ] 目标目录已有同名 → 自动加后缀，不覆盖
- [ ] 移动后封面、subfolder（逻辑目录）保持不变
- [ ] 单个文件移动失败（如目标只读）→ 跳过 + 警告，其它文件不受影响

### T3a 重关联到外部文件
- [ ] 单选 missing 文件 → 弹文件选择器 → 选目标 → path 更新、missing 清除、变 🔗
- [ ] 多选 N 个文件 → 选目录 → 按文件名匹配 → 成功 X 个 / 未找到 Y 个的汇总

- [ ] 替换后 label/kind/subfolder/origin 全部保留

### T3c 文件夹粒度
- [x] 在 📁 subfolder 节点右键 → 出现"整个文件夹转仓储/移到…/重关联…"
